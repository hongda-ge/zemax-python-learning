# Day51：执行获批的 Day23 零离焦基线控制

## 1. 为什么今天才连接 Zemax

Day50 只完成授权，没有运行任何光学分析。Day51 才通过审批指定的专用入口连接一次 ZOS-API。

把授权和执行分成两天，可以清楚回答两个问题：

1. 这个任务是否被允许运行？
2. 获准的任务实际运行后是否正确？

如果写在一个脚本里，程序可能在检查权限的同时已经开始执行，维护边界会变得模糊。

## 2. 和 Day50 的关系

Day50 冻结了：

- 允许案例：`defocus_004`；
- 残余离焦：`0.000 mm`；
- 最大执行次数：一次；
- 输入模型及 SHA256；
- Standard Spot 和 FFT MTF 配方；
- 输出根目录；
- 执行后的人工审核门 `CP09`。

Day51 必须逐项验证这些内容，不能自行扩大范围。

## 3. 为什么 `0.012 mm` 不写入 Zemax

这次变化是定位机构误差的教学假设，从 `+/-0.010 mm` 改为 `+/-0.012 mm`。它影响的是后续应该复核哪些证据，并不等于镜头厚度或像面位置本身立刻改变。

因此 Day51：

- 读取新的 Day22 变化证据；
- 证明证据中的定位精度是 `0.012 mm`；
- 但不把 `0.012 mm` 写入 LDE；
- 光学控制仍使用零离焦参考状态。

这叫做“变化证据与光学输入分离”。

## 4. 基线复现检查什么

使用相同的聚焦模型和分析配方，重新导出：

- 三个视场的 Standard Spot RMS；
- 30 cycles/mm 的 FFT MTF；
- 50 cycles/mm 的 FFT MTF。

新结果同时与三类冻结证据比较：

- Day8 Spot 基线；
- Day9 FFT MTF 基线；
- 历史 Day23 零离焦控制。

差值必须小于配置中的严格容差。这样才能确认分析环境、模型和解析流程没有悄悄变化。

## 5. 一次性授权怎样消费

执行前，计划脚本会在批准的输出目录中搜索结果文件：

```text
slot2_baseline_control_result.json
```

如果已经存在，就说明 Day50 的一次性授权已被使用，脚本会拒绝第二次执行。

这与 Day48 的防重放机制相同：一次性审批不是一个可以反复点击的运行按钮。

## 6. 第一步：运行 PLAN ONLY

```powershell
python scripts/demos/day51_approved_day23_baseline_control_plan.py
```

这一步只检查审批、指纹、案例和执行边界，不连接 Zemax。

## 7. 第二步：执行获批控制

PLAN ONLY 通过并经人工确认后运行：

```powershell
python scripts/demos/day51_execute_approved_day23_baseline_control.py
```

这一步会：

1. 创建一份隔离工作副本；
2. 建立一次 Standalone 连接；
3. 将像面写为零离焦参考值（只存在于内存）；
4. 导出一次 Spot 和一次 FFT MTF；
5. 比较历史基线；
6. 关闭连接；
7. 写入审计结果并停止。
