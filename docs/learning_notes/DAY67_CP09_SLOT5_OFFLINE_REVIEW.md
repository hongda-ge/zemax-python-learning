# Day 67：CP09 审核 Slot 5 离线复核结果

## 为什么今天做

Day66 已经消费了一次性授权并生成两个不同状态的子任务结果。Day67 需要确认这种状态分层是否真实、完整、安全，并判断下游是否具备释放条件。

## 和昨天的关系

Day66 完成了 Day26 重算，同时发现 Day27 缺少精确测量点。Day67 不重新计算，而是审核消费标记、JSON、CSV、输入指纹和权限边界。

## 核心概念

### 1. 执行成功不等于全部科学任务完成

Day66 程序正确完成，因此执行包审核可以 PASS。但 Day27 没有足够观测，科学复核仍是 BLOCKED。两个结论并不冲突。

### 2. 阻塞不是失败

Day27 缺少七个精确偏移点，只能说明当前证据不足。不能将它标记为光学 FAIL，也不能生成候选通过名单。

### 3. 阻塞向真正下游传播

Day28 使用 Day27 的包络候选，因此 Day27 未完成时，Slot 6 必须保持锁定。

### 4. 同槽兄弟任务不被过度阻塞

Day26 与 Day27 同处 Slot 5，但 Day26 不依赖 Day27。Day27 被阻塞不应撤销 Day26 已完成且审核通过的结果。

## 操作流程

先运行审核计划：

```powershell
python scripts/demos/day67_cp09_slot5_offline_review_plan.py
```

计划通过后生成 CP09 记录：

```powershell
python scripts/demos/day67_generate_cp09_slot5_offline_review.py
```

## 完成标准

- Day65 审批与 Day66 一次性消费一致；
- Day26 的 6 条明细和 3 条汇总有效；
- Day27 的 12 条状态记录和 7 个缺失点有效；
- 执行包 PASS、Day26 ACCEPTED、Day27 BLOCKED 三者分别表达；
- 只允许申请证据恢复规划；
- 不批准补测、插值、Slot 6 或工程变更。

## 简历表达参考

建立多任务复核的状态分层与依赖门控机制，将执行成功、科学完成和证据阻塞分别建模；通过同槽分支隔离保留独立有效结果，并将缺失观测精准传播至真实下游，避免全局误停或无证据放行。
