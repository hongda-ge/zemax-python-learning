# Day 4：真实 Zemax 单点基线验证

## 1. 今天解决的问题

Day 4 第一次把 Day 3 的纸面计划连接到真实 OpticStudio，但只处理风险最低的基准案例：

> 能否安全地打开模型副本、读取并写回同一个基准厚度、另存新文件，然后重新打开验证？

这不是为了改变设计，而是验证完整的 ZOS-API 写入链路。

## 2. 使用的文件

- 配置文件：`configs/baseline_case.yaml`
- 教学脚本：`scripts/demos/day4_single_baseline_case.py`
- 结果目录：`outputs/day4_single_case/`

运行命令：

```powershell
python scripts/demos/day4_single_baseline_case.py
```

## 3. 代码流程

1. 复用 Day 3 的配置、扫描范围、SHA256 和路径保护检查。
2. 将原始模型复制到独立输出目录，得到 `working_model.zmx`。
3. 建立 Standalone ZOS-API 连接并打开工作副本。
4. 读取 LDE 面 2，确认厚度为 `6.0075511 mm`。
5. 将同一个基准厚度写回 Zemax 内存。
6. 使用 `SaveAs` 另存为新模型，而不是覆盖原件或初始工作副本。
7. 重新打开新模型，验证厚度仍为 `6.0075511 mm`。
8. 比较操作前后的原始模型 SHA256，并输出 `result.json`。

## 4. 为什么“写回相同值”仍有意义

这相当于实验仪器的空载测试。即使数值没有变化，仍然验证了：

- ZOS-API 许可证和连接有效；
- 程序找到了正确的 LDE 面和单元格；
- Zemax 接受了 Python 的写入请求；
- `SaveAs` 和重新载入流程有效；
- 原始模型没有被覆盖。

如果一开始就扫描多个非基准值，出现错误时很难判断是连接、路径、写入还是参数本身造成的。

## 5. 实验结果

- ZOS-API：成功连接，真实 Zemax 后端。
- 面 2 半径：`-435.7604362 mm`。
- 面 2 厚度：`6.0075511 mm`。
- 保存后重新读取：厚度一致。
- 原始模型 SHA256：操作前后相同。
- ZOS-API：正常关闭。

## 6. 曾经遇到的关键错误

如果 YAML 写成显示值 `6.008 mm`，而模型内部精确值是 `6.0075511 mm`，在严格比较下会出现：

```text
ValueError: Surface 2 thickness does not match the YAML baseline.
```

这说明显示界面的三位小数不能代替模型内部的完整精度。正确做法是：配置中保存精确值，界面显示值只用于阅读。

## 7. 今天应掌握的内容

1. 原始模型、工作副本和另存结果是三个不同角色。
2. ZOS-API 中的修改首先发生在 Zemax 内存，只有保存后才写入新文件。
3. 写入后重新加载验证，比只相信屏幕输出更可靠。
4. 光学参数比较必须明确精度，不能把显示舍入值当成真实值。
