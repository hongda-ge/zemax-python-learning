# Day 7：五点厚度扫描与结果分析

## 1. 今天解决的问题

Day 3—Day 6 已证明单个案例可以安全执行。Day 7 第一次将流程扩展为完整的五点扫描：

> 面 2 空气间隔在较大范围内变化时，焦移和三个视场的 Spot 呈现什么规律，哪些案例会违反安全边界？

## 2. 使用的文件

```powershell

```

## 3. 为什么先计划、再基准、最后批量

Day 7 的执行思路不是直接启动五次 Zemax：

1. 先打印五个案例的文件名、厚度和基准标记，检查计划是否唯一。
2. 先单独执行基准 `case_003`，复现 Day 6 的焦移和三个视场 RMS。
3. 基准通过后，才顺序执行全部案例。
4. 每个案例都使用独立工作副本，执行厚度写入、Quick Focus、保存、Spot 导出和安全审计。
5. 预期的焦距越界记为 `rejected`，而不是伪装成成功结果。

这种逐级放行方式可以把批量实验的风险拆成可理解的小步骤。

## 5. 拒绝不是程序失败

最初运行时，`case_005` 以 `ValueError` 停止批次。后来流程明确区分两类情况：

- **unexpected failure**：连接失败、文件损坏、解析错误等，批次应停止。
- **constraint rejection**：计算完成，但结果违反事先声明的焦距边界，应记录后继续汇总。

这一区分非常重要。工程实验中“不满足约束”本身就是有价值的结果，不能删除，也不能填入虚假数据。

## 6. 离线分析规则

分析脚本只处理四个成功案例，并计算：

- 三个视场 RMS 的等权算术平均值；
- 三个视场中的最大 RMS；
- 焦移随面 2 厚度的变化；
- 被安全边界拒绝的案例。

透明的教学选择规则是：先最小化三视场平均 RMS，如相同则比较最差视场 RMS。按此规则，当前采样点中 `case_003 = 6.0075511 mm` 是较均衡的候选。

但这个平均值是 Python 生成的描述性指标，**不是 Zemax Merit Function，也不是最终工程结论**。

## 7. 从趋势中得到的认识

- 厚度增加时，所需焦移总体由正向变为负向。
- 0°、14°、20° 视场的变化方向不同，存在视场权衡。
- 基准值在当前粗采样中较均衡，但不能证明它是连续空间的严格最优点。
- 五点步长为 `0.5 mm`，只能定位候选区域，不能描述候选附近的细节。

## 8. 常见错误

- 把 `case_005` 的越界当成代码坏了，而没有区分约束拒绝。
- 一个案例失败后仍把空值用于平均，会污染结论。
- 让案例从上一个案例的修改结果继续运行，造成累积误差。
- 只保存汇总表，不保留每个案例的原始 Spot 和安全报告。
- 把简单平均当作隐藏的最终评分。

## 9. 今天应掌握的内容

1. 批量实验应经历计划、基准复现、顺序执行和离线分析四层。
2. 每个案例必须相互独立，并保留来源、状态和失败原因。
3. 安全边界是实验定义的一部分，越界案例必须诚实记录。
4. 粗扫描用于寻找候选区域，不能代替局部精细扫描。
