# Day47：Slot 1 离线复核执行审批

## 1. 为什么今天需要新的审批

Day46 只证明候选可信，并没有释放执行权限。如果把“审核通过”直接理解为“可以运行”，资格与授权就会混在一起。

Day47 单独回答：是否允许冻结的 `0.012 mm` 候选执行一次 Day22 离线复核？

## 2. 和 Day46 的关系

Day46 提供候选审核记录；Day47 还需要联合检查：

- Day42 的 Slot 1 确实只有 Day22；
- Day22 的执行类别是 `offline_only`；
- Day35 的 CP09 是执行后的人工审批门；
- 正式配置和候选文件的 SHA256 都没有变化。

只有这些条件同时成立，才能安全释放一个最小执行权限。

## 3. 什么是运行契约

运行契约规定授权怎样被使用。本次冻结：

- 任务：Day22 离线复核；
- 输入：Day45 候选及其 SHA256；
- 次数：最多一次；
- 入口：`scripts/demos/day48_execute_approved_day22_candidate.py`；
- 输出：只写入批准的隔离输出目录；
- ZOS-API：禁止；
- 新光学计算：禁止；
- 结束条件：完成 Slot 1 后立即停止，等待 CP09 人工审核。

未来的 Day48 必须实现并使用这个专用入口，不能直接让原 Day22 脚本读取正式配置。

## 4. 单槽释放

Day47 只释放 Slot 1。即使 Slot 1 运行成功，也不能自动运行 Day23 或其他下游任务。

原因是“程序运行成功”不等于“结果在科学上可接受”。执行后的证据还需要人工检查：

- 输入是否真的是批准候选；
- 结果是否完整；
- 安全标志是否全部通过；
- 数值变化能否合理解释；
- 是否满足进入下一槽的条件。

## 5. 第一步运行方式

```powershell
python scripts/demos/day47_slot1_offline_execution_approval_plan.py
```

PLAN ONLY 只评估是否可以批准，不生成审批记录，也不运行 Day22。

## 6. 完成标准

- Day46、Day42、Day35 证据指纹有效；
- 正式配置和候选指纹不变；
- 只批准 Slot 1 / Day22 / 离线 / 一次执行；
- 专用入口和隔离输出目录被固定；
- CP09 被指定为执行后的下一道人工门；
- Day47 本身没有执行任务；
- ZOS-API、正式配置修改和 Slot 2-6 继续锁定。

## 7. 第二步：生成执行审批记录

PLAN ONLY 通过后运行：

```powershell
python scripts/demos/day47_generate_slot1_offline_execution_approval.py
```

该脚本只生成审批记录。真正的 Slot 1 运行将在后续 Day48 通过专用入口进行。
