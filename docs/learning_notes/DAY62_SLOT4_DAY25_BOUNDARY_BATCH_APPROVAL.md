# Day 62：Slot 4 九点边界扫描批次审批

## 为什么今天做

Day61证明零偏移控制的授权、数据、复现和安全收尾均可信。Day62才有资格讨论是否释放九个非零边界案例，而且仍然只做审批，不执行光学分析。

## 和Day61的关系

Day61提供CP09控制审核；Day62把该审核作为九案例批次的前置门。没有Day61 PASS，Day62不能签发执行权限。

## 核心概念

### 1. 批次契约

审批前固定九个案例的身份、偏移、顺序、聚焦模型、Spot/MTF配方、输出目录和停止门，防止执行时临时改变范围。

### 2. 单通道与案例隔离

九个案例串行执行。每个案例使用独立工作副本和独立连接生命周期，任意时刻最多一个Standalone连接。

### 3. 执行异常与验收FAIL分离

- API、文件、指纹或分析异常：停止批次；
- 均衡教学指标FAIL：如实记录，继续运行后续案例。

验收FAIL是光学结果，不等于自动化程序失败。

### 4. 批次审批不释放下游

Day63完成后仍必须停在CP09。Slot5-6、连续容差和工程变更结论都不随本审批自动释放。

## 完成标准

- Day61审核与Day60控制证据有效；
- 九个非零案例及顺序与Day25配置一致；
- 冻结模型和历史九点证据指纹有效；
- 只释放一次九案例串行批次；
- 零偏移重跑、Quick Focus、优化和SaveAs保持禁止；
- Day62本身不连接Zemax、不创建模型副本、不计算光学结果。
