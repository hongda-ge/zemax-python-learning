# Day 14：LDE Solve 只读审计

## 今天解决的问题

Day 8 和 Day 13 改变 LDE 面2空气间隔时，输出报告显示面6曲率也随之变化：

```text
面2空气间隔：5.6075511 → 6.4075511 mm
面6曲率：   -18.3790414 → -18.4122991 mm
```

面6曲率的已观察变化范围约为 `0.0332577 mm`。这意味着实验中可能存在没有被明确说明的自动 Solve。Day 14 的目标是只读审计基准模型的 RadiusCell 和 ThicknessCell，确认哪些单元格固定、哪些是优化变量、哪些会依赖光学条件自动响应。

## 什么是 Zemax Solve

Solve 是 LDE 单元格的求值规则。单元格显示的数值不一定是独立手工输入值，它可能由其他参数或光学条件计算得到。

本次涉及三类状态：

- `Fixed`：固定数值；
- `Variable`：优化变量，只有运行优化器时才会由优化器调整；
- `MarginalRayAngle`：依赖型 Solve，为满足指定边缘光线角度而自动计算当前单元格。

`Variable` 和依赖型 Solve 不能混为一谈。仅仅设置为 Variable 不会在没有优化器时自行变化，而依赖型 Solve 会在相关系统参数变化后重新求值。

## 审计方法

1. 验证原始基准模型 SHA256；
2. 将基准模型复制到 `outputs/day14_lde_solve_audit`；
3. 使用 Standalone ZOS-API 打开工作副本；
4. 遍历全部8个顺序表面；
5. 读取每个表面的 `RadiusCell.Solve` 和 `ThicknessCell.Solve`；
6. 通过 `GetSolveData()` 读取当前 Solve 的有效详细参数；
7. 不修改单元格、不优化、不 Quick Focus、不 SaveAs；
8. 关闭连接后复核原始模型和磁盘工作副本 SHA256。

## 一次接口显示问题

第一次读取时，当前 `pythonnet` 将 Solve 枚举显示为数字：

```text
1 = Fixed
2 = Variable
5 = MarginalRayAngle
```

如果直接把数字字符串与 `Fixed` 比较，会把固定单元格错误分类为活动 Solve。脚本随后改为从本机 `ZOSAPI_Interfaces.dll` 动态读取枚举名称，避免依赖手写数字。

第二次读取详细属性时，代理对象还暴露了其他 Solve 接口的无效占位字段。脚本进一步改为只读取当前 Solve 类型官方定义的字段。对于 `MarginalRayAngle`，有效字段只有 `Angle`。

这说明 API 自动化不仅要读取数值，还要验证枚举翻译和接口代理行为。

## 最终审计结果

### 优化变量

以下11个单元格为 `Variable`：

- 面1至面5：曲率和厚度，共10个；
- 面6：厚度，共1个。

Day 8/13 没有运行局部或全局优化器，因此这些 Variable 不会仅因其变量身份自动被优化。面6厚度的变化来自脚本显式执行的 Quick Focus。

### 依赖型 Solve

唯一确认的依赖型 Solve 为：

```text
Surface 6 radius
Solve type: MarginalRayAngle
Angle: -0.100000001
```

这解释了为什么面2空气间隔变化后，面6曲率也发生连续变化。

### 固定单元格

物面和像面的 Radius/Thickness 在本次活动列表中未出现，因为它们读取为 Fixed。脚本最终报告12个活动单元格，其中11个是优化变量，1个是依赖型 Solve。

## 对 Day 8/13 的影响

原先容易把流程简写为：

```text
改变面2空气间隔 → Quick Focus → Spot
```

审计后，准确流程是：

```text
改变面2空气间隔
        ↓
MarginalRayAngle Solve 自动重算面6曲率
        ↓
Quick Focus 调整面6厚度
        ↓
计算 Spot
```

因此，Day 8/13 结果没有失效；它们仍准确记录了当前 Zemax 模型与补偿策略的响应。但是，它们不能被解释为“只有空气间隔改变、其他曲率全部冻结”的纯机械公差。

## 安全审计结果

- 审计表面数量：8；
- 活动单元格数量：12；
- ZOS-API 正常关闭；
- 原始模型 SHA256 未变化；
- 磁盘工作副本 SHA256 未变化；
- 未使用模型写入、优化、Quick Focus 或 SaveAs。

## 下一步

后续若要研究真正的空气间隔装调误差，应明确比较两种实验分支：

1. **保留 Solve 分支**：保持当前 `MarginalRayAngle` 与 Quick Focus，表示设计规则和补偿器都可用；
2. **冻结曲率分支**：在独立工作副本中将面6曲率转为固定值，并决定像面是否允许补偿，表示制造后曲率不再随间隔变化。

冻结 Solve 属于模型写操作，必须只对 `outputs` 下的副本执行，并先进行单案例验证，不能直接修改原始模型。

## 今天掌握的核心概念

- Variable 与依赖型 Solve 的行为不同；
- 参数扫描前必须审计活动 Solve 和补偿器；
- 自动化报告应记录模型如何响应，而不只记录最终指标；
- 发现隐藏模型规则后，应修正实验解释，而不是丢弃真实结果；
- 纯制造公差需要冻结制造后不可能自动改变的光学参数。
