# Day 63：获批的Day25九点边界批次

## 为什么今天做

Day62只签发了一次批次授权。Day63通过专用入口消费该授权，重新运行九个非零边界案例，并验证维护变化没有破坏历史光学证据。

## 和Day62的关系

Day62冻结了案例、顺序、模型、配方和安全规则；Day63只能按该契约执行，不能临时增删案例或扩大权限。

## 核心概念

### 1. 一次性批次授权

程序在第一个ZOS-API连接前写入消费标记。无论批次随后成功或异常，同一个审批都不能静默重用。

### 2. 独立案例生命周期

九个案例严格串行，每例创建独立工作副本、建立并关闭独立Standalone连接，任意时刻最多一个连接。

### 3. 六项摘要回归

每例比较Spot平均/最差、MTF30平均/最小、MTF50平均/最小，并检查均衡验收PASS/FAIL及失败指标签名是否复现。

### 4. 验收FAIL不是程序FAIL

`+0.040 mm`和`+0.045 mm`历史上不通过部分均衡指标。正确复现这些FAIL反而说明自动化证据链稳定。只有API、文件、指纹或数值复现异常才停止批次。

## 安全边界

- 不重跑零偏移控制；
- 禁止Quick Focus、优化和SaveAs；
- 模型与每个磁盘工作副本必须保持原指纹；
- 全部连接必须关闭；
- 不插值、不声明连续容差；
- 不释放Slot5-6或工程变更。

## 完成标准

- Day62审批只消费一次；
- 九案例按批准顺序各执行一次Spot和FFT MTF；
- 历史六项摘要与验收签名逐例复现；
- 九个连接全部关闭且模型副本未变；
- 结果写入隔离目录；
- 批次结束后停在CP09等待人工审核。
