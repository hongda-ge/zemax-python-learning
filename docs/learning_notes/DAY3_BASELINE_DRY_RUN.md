# Day 3：基准配置干运行与安全检查

## 1. 今天解决的问题

Day 3 没有连接 Zemax，而是先回答一个更基础的问题：

> 在真正修改光学模型之前，程序能否正确理解配置、扫描范围和原始模型？

这一步叫作 **Dry Run（干运行）**。它只展示准备执行的内容，不进行真实写入，是自动化实验中的第一道安全门。

## 2. 使用的文件

- 配置文件：`configs/baseline_case.yaml`
- 教学脚本：`scripts/demos/day3_baseline_dry_run.py`
- 原始模型：`models/Cooke 40 degree field.zmx`

运行命令：

```powershell
python scripts/demos/day3_baseline_dry_run.py
```

## 3. 代码流程

脚本依次完成五件事：

1. 用 `load_config()` 将 YAML 配置读取成 Python 字典。
2. 检查 `execution.enabled` 必须为 `false`，防止未经确认就执行。
3. 检查五个厚度值均位于安全范围 `1.0~10.0 mm` 内，并且包含基准值。
4. 计算原始 `.zmx` 文件的 SHA256，与配置中记录的指纹比较。
5. 检查原始模型路径与工作副本路径不同，然后打印五个计划案例。

计划厚度为：

```text
5.0075511, 5.5075511, 6.0075511, 6.5075511, 7.0075511 mm
```

其中 `6.0075511 mm` 是基准案例。

## 4. SHA256 指纹的含义

SHA256 是根据文件全部内容计算出的长字符串。这里它不是密码，也不是“每个程序天生自带的编号”，而是当前文件内容的指纹：

- 内容完全相同，通常会得到相同指纹。
- 文件只要发生很小变化，指纹一般也会明显改变。
- 它用于确认程序打开的是经过审核的模型，而不是同名但内容不同的文件。

## 5. 常见错误

- `execution.enabled` 被改成 `true`：干运行会拒绝继续。
- YAML 中的扫描值超出安全上下限：程序会报告不安全数值。
- 原始模型被编辑或替换：实际 SHA256 与配置记录不一致。
- 源模型与工作副本使用同一路径：存在覆盖原件的风险。
- 从错误目录运行：相对路径可能找不到配置或模型。

## 6. 今天应掌握的内容

1. YAML 用于描述实验，Python 用于读取和检查实验。
2. 真正运行 Zemax 前，应先验证参数范围、文件身份和写入路径。
3. Dry Run 不产生光学结果，但能提前发现大量配置错误。
4. 自动化的第一目标不是“跑得快”，而是“知道将要做什么，并且不会误伤原件”。
