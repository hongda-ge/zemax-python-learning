# Day74 CP09 恢复重试结果审核

## 为什么今天做

Day73 已成功消费新的重试授权并复现零偏移光学基线。Day74 需要把许可证恢复、授权消费、原始分析文件、模型哈希和连接关闭状态审核成正式证据。

## 和昨天的关系

Day73 是实际 ZOS-API 执行；Day74 是纯离线 CP09 审核。审核通过并不自动运行七点恢复批次。

## 核心概念

### 1. 恢复链完整性

完整链路为：

`Day70许可证失败 → Day71安全审核 → Day72新重试审批 → Day73成功重试 → Day74结果审核`

每一步都绑定路径和 SHA256，避免把旧授权或旧结果误认为新恢复证据。

### 2. 许可证恢复与光学恢复分开检查

- 许可证恢复：Standalone 连接建立、`license_valid=true`；
- 光学恢复：Spot 和 FFT MTF 与历史控制零差复现；
- 安全恢复：连接关闭，模型和磁盘副本不变。

三项全部通过，任务审核才是 PASS。

### 3. 审核通过不等于批次执行获准

Day74 只允许提出七点批次审批申请。七点案例、Day27 重算和 Slot 6 仍然锁定。

### 4. 原授权仍不可重复使用

Day72 授权已经由 Day73 消费。即使结果成功，也不能再次运行 Day73。

## 操作流程

先运行审核计划：

```powershell
python scripts/demos/day74_cp09_recovery_retry_review_plan.py
```

计划通过后生成审核记录：

```powershell
python scripts/demos/day74_generate_cp09_recovery_retry_review.py
```

## 完成标准

- Day72 审批只消费一次；
- Standalone 许可证和连接状态有效；
- Spot/MTF 与历史控制零差复现；
- 原始分析文件指纹有效；
- 模型与副本不变，连接关闭；
- 只开放七点批次审批申请资格；
- 重跑、额外重试、批次执行、Day27 重算和 Slot 6 继续锁定。

## 简历表达参考

建立 ZOS-API 故障恢复的 CP09 审核链，将许可证恢复、光学回归复现和模型安全审计分层验证，并通过 SHA256 绑定审批、消费标记、原始分析文件与结果，实现恢复流程的端到端可追溯性。
