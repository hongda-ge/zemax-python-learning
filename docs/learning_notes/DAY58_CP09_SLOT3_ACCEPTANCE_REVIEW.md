# Day 58：CP09 审核 Slot 3 离线验收

## 为什么今天做

Day57 已经生成三套验收结果，但一份脚本输出不能自动成为维护证据。Day58 要审核授权是否只消费一次、七点数据是否完整、规则是否正确、输出文件是否一致，以及历史结果是否复现。

## 和昨天的关系

Day57 是一次获批执行；Day58 是执行后的人工质量门。只有 Day58 通过，项目才具备申请 Slot 4 的资格。

## 核心概念

### 1. 任务通过不等于全部案例通过

严格场景只有 2/7 案例通过，但这不是程序失败。只要程序按照冻结规则正确、完整地报告通过与失败，任务审核仍可为 PASS。

### 2. 输出完整性

Day58 同时审核 JSON、明细 CSV、汇总 CSV 和验收矩阵图，并计算各自 SHA256。缺少任意文件都不能形成完整证据包。

### 3. 回归签名

不仅比较通过数量，还比较每套场景的通过案例和失败案例名单，防止规则实现出现不易察觉的变化。

### 4. 门控分离

CP09 审核通过只允许申请 Slot 4，不代表 Day25 已经可以运行。

## 操作流程

先运行只读审核规划：

```powershell
python scripts/demos/day58_cp09_slot3_acceptance_review_plan.py
```

通过后生成正式审核记录：

```powershell
python scripts/demos/day58_generate_cp09_slot3_acceptance_review.py
```

## 完成标准

- Day57 结果、消费标记和 Day56 审批指纹有效；
- 7 个案例、21 条明细和 3 条汇总完整；
- 三套历史通过/失败名单完全复现；
- 没有重跑、ZOS-API 或新光学计算；
- Slot 4-6 继续锁定。
