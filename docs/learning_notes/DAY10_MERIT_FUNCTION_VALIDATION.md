# Day 10：Merit Function 验证与三指标判断

## 今天解决的问题

Day 8 使用 Standard Spot 评价几何光线的集中程度，Day 9 使用 FFT MTF 评价不同空间频率下的对比度传递能力。Day 10 增加 Zemax Merit Function，用同一套综合惩罚规则检查三个 Pareto 候选。

本次任务只计算评价函数，不执行优化，因此 Zemax 不会继续改变曲率、厚度或其他变量。

## 首次基准检查发现的问题

第一次读取 `fine_005` 时得到：

- Merit Function value：0
- Operand count：1
- Operand type：BLNK

这个结果不是像质完美，而是候选模型没有保存真正的评价函数。之前由优化向导生成的 1602 行评价函数只存在于 Day 2 working model 中，没有进入后续使用的基准模型。

这说明配置文件中写有评价函数配方，并不代表模型文件中一定包含评价函数。自动化程序必须检查实际操作数数量和类型。

## 修正方法

1. 校验 Day 2 working model 的 SHA256。
2. 从模型中导出独立的 `.MF` 配方。
3. 冻结 `.MF` 文件哈希、操作数数量和定义指纹。
4. 对每个候选建立独立工作副本。
5. 仅在内存中加载同一份 `.MF` 配方。
6. 计算一次 Merit Function，不优化、不保存模型。

冻结信息：

- 操作数数量：1602
- `.MF` 文件 SHA256：`7C5D9C3A915A3A8EEFF61EE615535CA7DF68D4CB1EBF083392EA6FFBE34FF4CC`
- 加载后定义 SHA256：`B3263185E5BADC31B788CE77F50AADF852880F59DDA05D7CE7903260E14D3EE9`

导出前与重新加载后的定义指纹不同，是 Zemax 对 `.MF` 内容进行序列化规范化造成的。真正用于公平比较的是三个候选加载后完全一致且在计算前后保持不变的指纹。

## 三候选结果

| 候选 | 面 2 厚度 (mm) | Spot 平均 RMS (μm) | MTF30 平均值 | MTF50 平均值 | Merit Function |
|---|---:|---:|---:|---:|---:|
| fine_003 | 5.8075511 | 11.541 | 0.4456 | 0.2667 | 0.00305217948 |
| fine_004 | 5.9075511 | 11.140 | 0.4429 | 0.2388 | 0.00294948952 |
| fine_005 | 6.0075511 | 11.033 | 0.4266 | 0.2120 | 0.00291665833 |

Merit Function 越低越符合当前评价函数，因此排序为：

1. `fine_005`
2. `fine_004`，比 `fine_005` 高约 1.13%
3. `fine_003`，比 `fine_005` 高约 4.65%

## 为什么 Merit Function 与 Spot 趋势相同

当前评价函数由 RMS 点列图优化向导生成。它虽然包含不同视场、波长和厚度边界等大量操作数，但核心成像目标仍然是 RMS Spot。因此 Merit Function 是更完整的 Spot 综合惩罚，不是完全独立于 Spot 的第三种成像指标。

Merit Function 的绝对值依赖操作数、目标值和权重。`0.0029` 本身不能与另一套评价函数直接比较；同一评价函数下的候选相对差异才有意义。

## 当前教学结论

由于暂时没有指定探测器、像元尺寸或目标空间频率，不能正式宣布唯一工程最优值。当前保留三种用途：

- `fine_003 = 5.8075511 mm`：MTF 优先。
- `fine_004 = 5.9075511 mm`：暂定综合折中。
- `fine_005 = 6.0075511 mm`：Spot 与当前 Merit Function 优先。

其中 `fine_004` 相比 `fine_005`，Spot 和 Merit Function 只损失约 1%，但 MTF30 和 MTF50 分别提高约 3.8% 和 12.6%，因此适合作为教学实验中的暂定折中候选，而不是未经需求约束的最终答案。

## 今天掌握的核心概念

- 评价函数为零可能意味着没有有效操作数，不能直接解释为像质完美。
- 配置描述与模型实际状态必须分别验证。
- `.MF` 文件可以让多个模型使用完全相同的评价规则。
- 指纹用于证明操作数类型、参数、目标值和权重一致。
- “计算评价函数”和“执行优化”是两个不同动作。
- 没有真实需求和指标门槛时，应保留候选及其适用方向，而不是制造一个虚假的唯一最优解。
