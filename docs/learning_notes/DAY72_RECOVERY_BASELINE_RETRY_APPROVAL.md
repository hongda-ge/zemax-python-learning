# Day72 Day27 零偏移控制重试审批

## 为什么今天做

Day70 的一次性授权已被安全消费，但 Standalone ZOS-API 因许可证异常没有建立连接。Day71 完成失败审核并确认可以申请新审批，因此 Day72 的任务是签发一次边界清晰的新重试授权。

## 和昨天的关系

Day71 只证明失败发生在光学分析之前、模型未变且原授权不可复用。Day72 在此基础上批准 Day73 进行一次新的连接尝试，但不宣称许可证已经恢复。

## 核心概念

### 1. 失败后的重试必须重新授权

一次性授权的价值在于可审计。Day69 授权即使没有完成光学分析，也已在 Day70 连接前消费，因此不能直接再次运行同一个入口。

### 2. GUI恢复和API恢复是两类证据

OpticStudio GUI 能正常打开，说明桌面程序可用；Standalone ZOS-API 是否具备有效许可证，必须由新的 API 连接尝试验证。Day72 只批准该验证尝试。

### 3. 最小权限重试

新授权只包含：

- 一个零偏移控制；
- 一个隔离工作副本；
- 一个 Standalone 连接生命周期；
- 连接成功后各一次 Spot 和 FFT MTF；
- 一份成功或失败结果。

七点恢复批次、Day27 重算和 Slot 6 都没有释放。

### 4. 重试失败也必须形成证据

Day73 在连接前消费新授权。如果许可证仍然失败，不能再次点击运行，而应保存失败结果并重新进入 CP09 审核。

## 操作流程

先运行审批计划：

```powershell
python scripts/demos/day72_recovery_baseline_retry_approval_plan.py
```

计划通过后生成审批记录：

```powershell
python scripts/demos/day72_generate_recovery_baseline_retry_approval.py
```

## 完成标准

- Day71 审核和重试申请资格有效；
- 原 Day69 授权保持已消费且不可复用；
- 模型、Day70 配方和历史零偏移控制指纹有效；
- 只释放 Day73 一次重试；
- 成功和失败路径都停在 CP09；
- 七点批次、Day27 重算和 Slot 6 继续锁定。

## 简历表达参考

构建 ZOS-API 异常后的最小权限重试机制，通过新决策编号、冻结输入指纹、一次性授权消费和成功/失败双路径门控，避免许可证故障后的无审计重复执行，并保持光学证据链可追溯。
