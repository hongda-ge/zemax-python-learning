# Day 68：Day27 精确状态证据恢复计划

## 为什么今天做

Day67 已确认 Day27 不是光学失败，而是缺少七个精确测量状态。Day68 的任务是把这项证据缺口转化为安全、可审计的恢复路线。

## 和昨天的关系

Day67 只允许申请恢复规划，没有批准补测。Day68 因此只能确定点位、配方、工作量和审批阶段，不能连接 Zemax。

## 核心概念

### 1. 最小充分测量集

完整复核四个命令包络需要补齐：

`-0.012、+0.008、+0.012、+0.018、+0.022、+0.032、+0.042 mm`

七个点均未测量，且每一点都对应至少一个候选的缺失端点。若目标是完整评价全部四个候选，任何一点都不能删除。

### 2. 为什么需要再次做零偏移控制

虽然 Day60 已经复现过零偏移基线，但新的七点补测属于新的高风险 ZOS-API 批次。先通过控制组确认模型、像面和分析配方没有漂移，可以降低整批错误传播风险。

### 3. 分段审批

恢复路线分为四段：

1. 零偏移控制及 CP09；
2. 七点补测批次及 CP09；
3. Day27 离线包络重算及 CP09；
4. Slot 6 释放审核。

前一段完成不自动释放后一段。

### 4. 计划工作量不是执行授权

如果所有后续阶段都分别获批，预计需要 8 次连接、8 个独立副本、8 次 Standard Spot 和 8 次 FFT MTF。Day68 只记录这些资源需求，不执行它们。

## 操作流程

先验证计划：

```powershell
python scripts/demos/day68_day27_evidence_recovery_plan.py
```

验证通过后生成计划记录：

```powershell
python scripts/demos/day68_generate_day27_evidence_recovery_plan.py
```

## 完成标准

- 七个缺失点与四个候选关系完整；
- 目标像面位置由冻结参考距离精确计算；
- Spot 与 FFT MTF 配方保持一致；
- 基线控制、七点批次、离线重算和 Slot 6 审核相互分离；
- Day68 不产生任何执行权限。

## 简历表达参考

将科学证据缺口转化为最小充分实验集和分阶段恢复流程，冻结光学配方、模型指纹、资源预算及审批门；通过控制组优先、逐案例隔离和下游门控，构建可审计的 ZOS-API 补测计划。
