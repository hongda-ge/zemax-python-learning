# Day 57：执行获批的 Day24 离线验收

## 为什么今天做

Day56 只签发了一次 Slot 3 权限。Day57 才真正消费该权限，把已审核的七个光学测量点转换为验收矩阵。

## 和昨天的关系

- Day52 提供零偏移控制；
- Day55 提供六个非零偏移案例；
- Day56 冻结三套阈值、入口和输出边界；
- Day57 只执行一次离线分类，并停在 CP09。

## 核心概念

### 1. 授权消费

执行前创建消费标记。同一 Day56 审批不能重复使用，避免无意中生成多套互相混淆的正式结果。

### 2. 数据拼装

控制组和实验组来自不同批次，但都经过 CP09 审核。Day57 通过审核记录中的路径和 SHA256 恢复七点数据，而不是搜索“最新文件”。

### 3. 四指标 AND 规则

Spot 均值、最差 Spot、MTF30 最低值和 MTF50 最低值分别判断。只有四项全部通过，一个测量点才通过该场景。

### 4. 历史复现

Day57 的通过名单必须与历史 Day24 完全一致。这属于回归测试：它验证维护流程没有改变科学规则。

## 操作流程

先执行只读规划：

```powershell
python scripts/demos/day57_approved_day24_acceptance_execution_plan.py
```

规划通过后再执行一次获批任务：

```powershell
python scripts/demos/day57_execute_approved_day24_acceptance.py
```

## 完成标准

- 七个案例拼装完整；
- 严格、均衡、宽松三套结果复现历史 Day24；
- 审批只消费一次；
- 不连接 ZOS-API、不计算新光学指标；
- 不插值、不声称连续公差；
- Slot 4-6 继续锁定并等待 CP09。

## 简历表达参考

实现基于冻结证据与一次性授权的离线光学验收流水线，将七点残余离焦 Spot/MTF 指标按四指标 AND 规则自动分类，并通过历史结果回归验证、SHA256 数据绑定和人工门控保证结果可复现、可审计。
