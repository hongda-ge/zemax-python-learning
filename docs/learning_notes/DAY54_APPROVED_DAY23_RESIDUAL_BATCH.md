# Day54：执行获批的六案例残余离焦批次

## 1. 为什么今天才真正连接 Zemax

Day53 已经把案例范围、分析配方和安全规则写进审批记录。Day54 才通过指定入口消费这一次授权，运行六个非零残余离焦案例。

## 2. 和 Day53 的关系

Day53 相当于签署实验单；Day54 严格按照实验单操作。脚本会核对审批 SHA256、案例身份、输出目录和禁止事项，防止执行范围被临时扩大。

## 3. 一次授权消费标记

脚本在连接 Zemax 前创建排他的消费标记。这样即使第几个案例发生意外，审批也已经明确被使用，不能直接重复运行。失败后应先查看已有证据，再申请新的执行权限。

## 4. 每个案例如何隔离

每个偏移都执行相同流程：

1. 从冻结聚焦模型建立独立工作副本；
2. 打开一个 Standalone ZOS-API 连接；
3. 只在内存中写入像面残余偏移；
4. 导出 Standard Spot；
5. 导出 FFT MTF；
6. 检查模型和磁盘副本指纹；
7. 关闭连接，再进入下一个案例。

## 5. 为什么还要核对历史 Day23

本次变化是定位精度教学假设从 `0.010 mm` 改为 `0.012 mm`，它不是 Zemax 光学模型输入。因此相同模型、相同偏移和相同分析配方应复现历史 Day23 光学结果。逐项核对能发现模型或配方被意外改变。

## 6. 第一步运行方式

```powershell
python scripts/demos/day54_approved_day23_residual_batch_plan.py
```

PLAN ONLY 不消费授权、不创建输出、不连接 Zemax。

## 7. 完成标准

- 六个非零案例与 Day53 审批完全一致；
- 零偏移基线不被重复执行；
- 每个案例都有独立副本和连接生命周期；
- Spot 与 FFT MTF 复现历史证据；
- 所有连接关闭、所有指纹不变；
- 不运行 Quick Focus、优化或 SaveAs；
- 完成后停在 CP09，Slot3-6 仍锁定。

## 8. 第二步

PLAN ONLY 通过后再运行：

```powershell
python scripts/demos/day54_execute_approved_day23_residual_batch.py
```

第二步会真正消费一次授权并连接 Zemax，不能随意重复运行。
