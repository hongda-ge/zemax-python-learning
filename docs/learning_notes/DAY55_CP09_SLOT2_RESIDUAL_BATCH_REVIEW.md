# Day55：CP09 审核 Slot 2 六案例批次

## 1. 为什么 Day54 全是 PASS 还要审核

程序打印 PASS 只能说明它认为自己完成了流程。维护者还需要独立检查：审批是否只使用一次、六个案例是否完整、总表是否与案例报告一致、原始分析文本是否存在、连接是否全部关闭，以及模型指纹是否保持不变。

Day55 把这些条件转换为一份可以追溯的 CP09 审核记录。

## 2. 和 Day54 的关系

Day54 负责真实计算，Day55 不再计算任何光学指标，只读取已有证据。这样可以避免“负责执行的代码同时给自己批准通过”。

## 3. 什么是批量回归验证

本次定位精度教学假设从 `0.010 mm` 变为 `0.012 mm`，但它不是 Zemax 模型输入。因此六个相同偏移的 Spot 和 MTF 应复现历史 Day23 结果。

Day55 对每个案例分别检查：

- Spot 平均值与最差视场值；
- MTF30 平均值与最小值；
- MTF50 平均值与最小值；
- 新旧结果的最大绝对差；
- 案例 JSON、Spot 原始文本、MTF 原始文本的 SHA256。

## 4. 为什么“任务 PASS”不等于“性能 PASS”

`defocus_001` 的 MTF50 最小值较低，这是光学实验结果，不是程序错误。Day55 的 PASS 表示：

- 获批的六个案例都正确执行；
- 输出完整且可以追溯；
- 新结果复现冻结证据；
- 安全边界没有被破坏。

是否满足某组验收门槛属于 Day24 的职责，不能在 Day55 偷换判断标准。

## 5. 简历价值

这一阶段可以概括为：

> 设计基于 SHA256、逐案例原始证据和人工审批门的 ZOS-API 批量回归验证流程，实现六案例 Spot/FFT MTF 结果的可复现性与安全边界审计。

它展示的是实验自动化、质量保证和可追溯维护能力，而不只是编写一个循环调用 Zemax。

## 6. 第一步运行方式

```powershell
python scripts/demos/day55_cp09_slot2_residual_batch_review_plan.py
```

PLAN ONLY 不生成审核文件、不连接 Zemax，也不释放 Slot 3。

## 7. 完成标准

- 六个案例身份与偏移完整；
- 六份案例 JSON 和十二份原始分析文本存在并获得指纹；
- 总表与各案例指标一致；
- 历史结果逐案例复现；
- 一次授权、连接关闭和模型哈希检查全部通过；
- 审核状态为 PASS；
- Slot 3 仍未获得执行权限。

## 8. 第二步

PLAN ONLY 通过后运行：

```powershell
python scripts/demos/day55_generate_cp09_slot2_residual_batch_review.py
```

它只生成 JSON 和 Markdown 审核记录。之后还要单独审批 Slot 3 / Day24。
